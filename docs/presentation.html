Run the demo, step by step

Prepare the Python environment first. Use a disposable workspace. The browser shows commands only; it does not execute them or make model API calls.

1. Enter the repository and activate Python

# Replace this path with your checkout location.
cd /path/to/mini_coding_agent

# Run once if the virtual environment does not exist.
python3 -m venv .venv

# Activate in every new terminal used for the demo.
source .venv/bin/activate
pip install -e '.[test]'

Run all remaining commands from this same terminal. On Windows, use .venv\Scripts\activate instead of source.

2. Prepare the selected model service



3. Create a disposable target workspace
DEMO_DIR=$(mktemp -d)
cp -R benchmarks/tasks/add_bug/. "$DEMO_DIR/"
printf 'Target workspace: %s\n' "$DEMO_DIR"
This copies a tiny fixture. The agent will edit the copy, not its own implementation or the original fixture.




4. Run the agent


5. Inspect the edited file and trace

python -m json.tool /tmp/mini-agent-demo-result.json

What this demo does—and does not include
An explicit inventory of implemented mechanisms and absent technology. This is a small custom implementation, not a production coding system.


Included in the current code


A custom agent loop
Python orchestration of model requests, validated actions, observations, and termination. No agent framework is required.


Model adapters and named profiles
Ollama and an OpenAI-compatible adapter. DeepSeek uses native function calls; the local profile uses JSON action text.


Local repository tools
List, read, edit, replace existing Python files, and run pytest in the selected workspace.


Optional MCP search
A bundled stdio client/server exposes literal substring search. It is a tool transport, not the agent's reasoning engine.


Sequential read-only batches
Up to eight host-approved read-only calls per native response. No concurrent tool execution.


Run logs and fixture checks
JSONL events, action traces, provider metrics, and a small independent regression harness for development.


Not included


An agent framework
No LangChain, LangGraph, or equivalent agent framework. The loop and adapters are implemented directly.


RAG or semantic retrieval
No embedding model, vector database, semantic index, or retrieval-augmentation pipeline. Local string search is not presented as RAG.


Execution isolation
No Docker backend or VM sandbox. File path checks and temporary directories do not isolate test code from host permissions.


Persistent agent memory
No cross-run memory or automatic knowledge store. Conversation history stays in the current run; logs are diagnostics, not recalled memory.


Multi-agent or A2A coordination
No delegation, agent messaging protocol, concurrent agents, or shared-work coordination.


Production delivery or rigorous evaluation
No automated patch export, PR creation, merge, deployment, or broad validated capability study. New-file creation is also not implemented.




RAG can use a retrieval tool, but RAG is not simply a tool
A retriever may be exposed through the same tool interface. RAG also involves retrieving relevant external information and supplying it as context for generation. This demo has no such pipeline; its MCP search is a literal code-search operation.
